# Game design documents

This directory is the home for Gens game-design material. Documents capture the
intended player experience and system relationships; they are not a substitute for
engineering contracts, schemas, or tests. See the [documentation map](../README.md)
for the rest of the project documentation.

## Reading order

1. Start with [About Gens](gens-about.md) for the pitch, then the core design for the overall vision and vocabulary.
2. Read the foundational catalogs for shared character concepts.
3. Consult individual system specifications as a feature is planned.
4. Use world references and starting-region documents for authored content.
5. Use the [Feature Roadmap](gens-feature-roadmap.md), the [Canonical Object & Data Registry](../gens-canonical-registry-design.md), and the [Design Authority Registry](../gens-design-authority-registry.md) to see how systems and content fit together and in what order they should be built.

## Maintenance

- Keep one top-level heading per document and use descriptive kebab-case filenames.
- Link related documents with relative links rather than duplicating their rules.
- Record unresolved decisions explicitly; do not silently present proposals as implemented behavior.
- Update this index whenever a design document is added, removed, or renamed.
