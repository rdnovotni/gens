# Native accessibility

Every retained node has role, name, description, value, checked state, and decorative status. `UiRoot.CaptureSemantics` exports only the active modal scope, omits decorative nodes, and identifies the focused node. `ValidateSemantics` reports unnamed interactive controls. Buttons, toggles, headings, dialogs, scroll regions, portraits, and the estate preview carry explicit semantics; portraits expose structured appearance text as descriptions. Modal focus remains trapped and restored by `UiRoot`.

The Windows bridge (`WindowsAccessibilityBridge`) publishes semantic snapshots through two paths: the legacy `NotifyWinEvent` focus announcement some assistive technology still relies on, and a real UI Automation fragment-provider tree (`Gens.Accessibility.Windows.Uia`). `SemanticNodeSnapshot` now carries root-relative logical `Bounds` (from `UiNode.Bounds`, already root-relative — no per-parent coordinate accumulation needed); `UiaFragmentProvider`/`UiaFragmentRootProvider` implement `IRawElementProviderSimple`/`IRawElementProviderFragment`/`IRawElementProviderFragmentRoot`, map `AccessibilityRole` to UIA control types and Invoke/Toggle/Scroll pattern support (`UiaRoleMapping`), navigate the snapshot tree via `SemanticFragmentIndex` (nodes are indexed by structural path, not by `SemanticNodeSnapshot.Id` — `UiRoot.Snapshot` falls back to a control's type name when unset, so plain `Id` is routinely duplicated across sibling controls), and convert bounds to screen pixels via `ClientToScreen`/`GetDpiForWindow` against the real HWND resolved from the SDL window handle (`SdlWindow.NativeSdlWindowHandle` → `Gens.Platform.Sdl.SdlWindowsMessageHook.GetHwnd`).

Known gaps in this pass, not yet certified:
- `Invoke`/`Toggle` on the UIA pattern providers are no-ops — routing a screen-reader-initiated action back into a live `UiRoot` command would require broadening `IAccessibilityBridge.Publish` beyond a read-only snapshot; role/name/state/tree/bounds/focus are real, activation is not yet wired.
- Point-based hit-testing (`IRawElementProviderFragmentRoot.ElementProviderFromPoint`) returns the root rather than the actual element under the point.
- `WindowsAccessibilityBridge.HandleWindowsMessage` checks `lParam == OBJID_CLIENT` and forwards `wParam`/`lParam` unchanged to `UiaReturnRawElementProvider`, matching documented `WM_GETOBJECT` semantics, but delivering that call's return value back through SDL's `SDL_SetWindowsMessageHook` callback has not been confirmed against a live window.
- No automated test can attach a real UIA client; `Gens.Accessibility.Windows.Tests` covers the provider's logic (role mapping, tree navigation including sibling controls that share a fallback `Id`, property/pattern/bounds/focus/runtime-id resolution) directly, in-process, without COM activation. **Attaching NVDA, Narrator, or Windows Accessibility Insights against a packaged build to confirm the tree reads correctly, `WM_GETOBJECT` round-trips through a live SDL window, and focus is announced remains a required manual verification step before this counts as certified.**

macOS NSAccessibility and Linux AT-SPI currently use the explicit null bridge. These, and the gaps above, are release gaps, not supported features.

Keyboard navigation uses Tab/Shift+Tab, Enter/Space, Escape, and scroll keys. Tests cover focus, modal trapping, semantic names, and snapshot focus. `MotionPolicy` classifies Essential, Informational, and Decorative motion: Reduced disables Decorative SceneView updates and caps Informational transitions at 120 ms; None permits only Essential motion. The estate preview is static today. High contrast replaces control surfaces with black/white, thicker borders, and a yellow/blue focus treatment; statuses retain text, not color alone.
